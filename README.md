# MediReminder 3.4.2 — یادآور هوشمند دارو

**یادآور هوشمند دارو** برنامه‌ای آفلاین‌محور برای ثبت برنامه دارویی، یادآوری نوبت‌ها و مرور سوابق ثبت‌شده است.

- **وب‌سایت:** https://medi-reminder-nu.vercel.app
- **کافه‌بازار:** https://cafebazaar.ir/app/com.tahmoures54.medireminder
- **فناوری‌ها:** React 19، TypeScript، Vite، Capacitor و IndexedDB
- **مجوز:** MIT

> این برنامه ابزار یادآوری و ثبت اطلاعات است؛ جایگزین پزشک یا داروساز نیست. دوز و زمان مصرف دارو را مطابق دستور متخصص رعایت کنید.

## امکانات

- ثبت، ویرایش و حذف داروها و برنامه مصرف آن‌ها
- زمان‌بندی بر اساس زمان مطلق نوبت بعدی
- تکرار هشدار نوبت در انتظار تا تأیید مصرف یا تعویق آن
- ثبت وضعیت نوبت‌ها و مرور گزارش مصرف
- پیگیری موجودی دارو
- خروجی و اشتراک‌گذاری گزارش و پشتیبان‌گیری از اطلاعات
- راهنمای مجوز اعلان‌ها و تنظیمات باتری اندروید
- کارکرد محلی؛ اطلاعات دارو و اعتبار بسته‌ها در فضای ذخیره‌سازی دستگاه نگهداری می‌شوند

## نصب و استفاده

در اندروید، برنامه را از کافه‌بازار نصب کنید. پس از نصب:

1. مجوز اعلان‌ها را فعال کنید.
2. در گوشی‌هایی که محدودیت پس‌زمینه دارند، تنظیم باتری برنامه را روی حالت بدون محدودیت قرار دهید و در صورت نیاز Autostart را فعال کنید.
3. صدای کانال اعلان برنامه را در تنظیمات گوشی قطع نکنید.
4. برای محافظت از اطلاعات، از قابلیت پشتیبان‌گیری برنامه استفاده کنید.

عملکرد اعلان‌ها به مجوزهای اندروید، تنظیمات سازنده گوشی و وضعیت اجرای برنامه وابسته است. **هیچ برنامه‌ای نمی‌تواند تداوم هشدار را در همه شرایط، از جمله توقف اجباری برنامه، تضمین کند.**

## مدیریت اعلان‌ها و محدودیت‌ها

- زمان نوبت بعدی با مقدار مطلق `nextDoseAt` (میلی‌ثانیه از epoch) مشخص می‌شود؛ تیک رابط کاربری صرفاً برای نمایش است.
- اندروید از اعلان‌های محلی بومی استفاده می‌کند و صف اعلان‌های آینده محدود است: حداکثر ۴۵۰ اعلان در صف و حداکثر ۳۶ نوبت پیگیری برای هر دارو در شرایطی که محدودیت صف مانع نشود.
- هشدارهای پیگیری بومی با فاصله حدود ۱۵ دقیقه زمان‌بندی می‌شوند. پوشش صف نامحدود نیست؛ برای پرشدن مجدد صف، برنامه باید فرصت اجرا یا بازگشت به foreground را داشته باشد.
- توقف اجباری برنامه یا محدودیت‌های اختصاصی سازنده گوشی ممکن است مانع اجرای مجدد اجزای برنامه شوند تا کاربر برنامه را دوباره باز کند.
- پیش از انتشار هر نسخه، اعلان، تکرار هشدار، تعویق، ثبت مصرف، راه‌اندازی مجدد گوشی و تنظیمات باتری را روی دستگاه واقعی آزمایش کنید.

## بسته‌های کارت دارو و پرداخت کافه‌بازار

ثبت اولین دارو یک‌بار رایگان است و ویرایش داروهای ثبت‌شده رایگان می‌ماند. پس از آن، هر عملیات افزودن دارو یا حذف دارو یک توکن مصرف می‌کند؛ حذف دارو توکن را برنمی‌گرداند. بسته ۱۰ توکن یعنی ۱۰ عملیات مصرفی، نه ظرفیت ۱۰ داروی هم‌زمان. اعتبار توکن‌ها و مصرف آن‌ها در IndexedDB و به‌صورت محلی ثبت می‌شود.

شناسه‌های فعال بسته‌ها در کد:

| شناسه محصول | اعتبار |
|---|---:|
| `medireminder_tokens_10` | ۱۰ توکن |
| `medireminder_tokens_30` | ۳۰ توکن |
| `medireminder_cards_100` | ۱۰۰ توکن |

قیمت از کافه‌بازار دریافت می‌شود و در کد ثابت نشده است. شناسه‌های قدیمی `medireminder_cards_3`، `medireminder_cards_10`، `medireminder_cards_25` و `medication_card_1` فقط برای پردازش خریدهای قدیمیِ قابل بازیابی نگه داشته شده‌اند و نباید در فهرست خرید جدید نمایش داده شوند.

### روند تحویل اعتبار

1. برنامه خریدهای قابل بازیابی را از بازار بررسی می‌کند.
2. توکن خرید و اعتبار متناظر در تراکنش IndexedDB ثبت می‌شوند.
3. پس از ذخیره اعتبار، برنامه تلاش می‌کند خرید را با `consumeProduct` مصرف کند تا کاربر بتواند همان بسته را دوباره بخرد.
4. ثبت اعتبار با توکن خرید idempotent است؛ پردازش دوباره یک توکن نباید اعتبار را دوباره افزایش دهد.
5. اگر مصرف توکن خطا دهد، اعتبار ذخیره‌شده حفظ می‌شود و برنامه می‌تواند بعداً مصرف را دوباره امتحان کند.

### محدودیت بازیابی خرید

این نسخه دفتر ثبت خرید ابری ندارد. اعتبار و سابقه توکن‌های تحویل‌شده به‌صورت محلی در IndexedDB ذخیره می‌شوند. پس از مصرف موفق خرید، پاک‌کردن داده‌های برنامه یا حذف و نصب مجدد ممکن است باعث از دست رفتن اعتبار محلی شود؛ بازیابی این اعتبار از بازار **تضمین‌شده نیست**. ورود به همان حساب بازار به‌تنهایی تضمین نمی‌کند بسته مصرف‌شده دوباره بازیابی شود.

کلید عمومی پرداخت باید در GitHub Actions با نام Secret زیر تنظیم شود:

`BAZAAR_RSA_PUBLIC_KEY`

کلید خصوصی یا اطلاعات محرمانه امضا را در مخزن یا فایل README قرار ندهید. شناسه‌ها و نوع محصولات در پنل توسعه‌دهندگان بازار باید با کد هماهنگ باشند. خرید واقعی را فقط روی نسخه اندرویدی نصب‌شده از بازار آزمایش کنید و برای آزمون مکرر از روش آزمایشی مجاز استفاده کنید.

### آزمون پرداخت پیش از انتشار

- خرید موفق، افزایش دقیق مانده توکن‌ها
- لغو خرید بدون اعطای اعتبار
- بازگشت از بازار به برنامه
- قطع اینترنت یا بسته‌شدن برنامه در میانه فرایند
- خطای `consumeProduct` و تلاش مجدد
- جلوگیری از اعطای دوباره اعتبار برای یک توکن
- شکست ذخیره‌سازی پیش از مصرف خرید و بازیابی آن در اجرای بعدی
- کاهش اتمیک مانده توکن هم‌زمان با افزودن یا حذف دارو
- حفظ مانده اعتبار در صورت شکست تراکنش IndexedDB
- خرید دوباره همان بسته پس از مصرف موفق خرید قبلی

## معرفی برنامه برای کافه‌بازار

**یادآور هوشمند دارو؛ داروهایت را به‌موقع مصرف کن!**

با ثبت نام دارو، دوز و فاصله زمانی مصرف، برنامه دارویی خود را منظم‌تر مدیریت کنید. یادآوری نوبت‌ها، پیگیری موجودی، ثبت وضعیت مصرف و تهیه گزارش از سوابق ثبت‌شده به شما کمک می‌کند اطلاعات دارویی را راحت‌تر مرور کنید.

این برنامه برای افرادی که چند دارو مصرف می‌کنند، سالمندانی که به یادآوری نیاز دارند و اعضای خانواده‌ای که در مدیریت دارو مشارکت می‌کنند مفید است. گزارش ثبت‌شده می‌تواند برای گفت‌وگو با پزشک همراه برده شود؛ این گزارش به‌تنهایی اثبات قطعی مصرف دارو نیست.

اعلان‌ها به مجوزها و تنظیمات گوشی وابسته‌اند و ممکن است تحت تأثیر محدودیت باتری یا توقف اجباری برنامه قرار گیرند. برنامه جایگزین توصیه پزشک یا داروساز نیست.

## توسعه و اجرای محلی

نیازمندی‌ها: Node.js نسخه ۲۰٫۹ یا جدیدتر و npm نسخه ۱۰٫۱ یا جدیدتر.

```bash
npm ci
npm run dev
```

فرمان‌های بررسی:

```bash
npm run typecheck
npm test
npm run build
# یا اجرای همه بررسی‌ها به‌ترتیب:
npm run check
```

برای همگام‌سازی پروژه وب با اندروید:

```bash
npx cap sync android
```

### ساخت APK/AAB

در GitHub به بخش **Actions** بروید و workflow ساخت APK را اجرا کنید؛ workflow همچنین طبق تنظیمات خودش ممکن است با push کردن tag نسخه اجرا شود. پس از اتمام موفق، artifact مربوط به APK را برای نصب در بازارهایی که APK می‌پذیرند و AAB را برای فروشگاه‌هایی که AAB می‌خواهند دریافت کنید.

برای امضای پایدار نسخه‌های بعدی، کلید امضا را در محل امن نگه دارید و Secrets زیر را در GitHub Actions تنظیم کنید:

- `ANDROID_KEYSTORE_BASE64`
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`

اگر کلید امضا در artifact تولید شد، آن را فوراً دانلود و به‌صورت امن پشتیبان‌گیری کنید. فایل کلید و رمزها را عمومی نکنید. برای ساخت کلید محلی:

```bash
bash scripts/generate_upload_keystore.sh ./signing-key
```

## ساختار فنی

- `src/App.tsx`: جریان اصلی رابط و وضعیت برنامه
- `src/components/`: فرم‌ها، کارت دارو، مودال‌ها و گزارش
- `src/db/database.ts`: ذخیره‌سازی داروها، وضعیت برنامه و دفتر محلی توکن‌های خرید در IndexedDB
- `src/hooks/useDoseActions.ts`: عملیات مصرف، تعویق، توقف و بازنشانی نوبت
- `src/utils/alarms.ts`: پل اعلان‌ها میان Service Worker و اعلان‌های محلی اندروید
- `src/utils/permissions.ts`: بررسی مجوزهای اعلان و آلارم
- `src/services/bazaarBilling.ts`: اتصال بازار، بازیابی خرید، ثبت اعتبار و مصرف توکن

برنامه backend یا حساب کاربری ابری برای اطلاعات دارو و اعتبار محلی ندارد.

این پروژه با مجوز MIT منتشر می‌شود. نرم‌افزار صرفاً برای یادآوری و ثبت اطلاعات است و جایگزین تشخیص، تجویز یا توصیه پزشک و داروساز نیست. کاربر باید برنامه درمانی خود را طبق دستور متخصص دنبال کند و پیش از اشتراک‌گذاری گزارش، محتوای آن و گیرنده را بررسی کند.
